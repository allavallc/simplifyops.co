# Story 50 - Hermes upgrade protocol

## Status
**Done (branch `story-50-hermes-protocol`).** P1 of the blueprint adoption backlog.

## Goal
Formalize the Hermes runtime upgrade procedure as a canonical, repeatable protocol — pin → inspect →
install → test → re-pin — grounded in the 0.19.0 → 0.20.5 run ([[story-33]]) and the
[[hermes-upgrade-pin-workflow]] learning, so future upgrades are a bounded, governed operation rather
than ad-hoc.

## Decision — patch script deferred (not built)
The backlog line listed `scripts/apply_hermes_runtime_patches.py` + patch/layout tests. Investigation
found **zero current runtime patches**: the `codex_runtime.py` backfill was **resolved upstream in
0.20.5**, and the old `EnvironmentFile` re-add applied only to the now-stopped **legacy**
`hermes-gateway.service` (current `simplifyops-*` units are repo-owned, not regenerated by the
installer). Building the applier now would be an **empty patch framework** — scaffolding that CLAUDE.md
("No Short-Term Fixes", "Minimal Code") forbids. The doc captures the **mechanism spec** so the script
can be created correctly the first time a real patch is needed. Tracked in
[[stories-parkinglot]] until then.
