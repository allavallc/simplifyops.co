# SimplifyOps.co

SimplifyOps.co is an automated weekly content system and Jekyll site for operations, management, and strategy.

It combines:
- a public blog on GitHub Pages
- a Hermes-powered CEO agent that researches topics and drafts posts
- a human approval step before publishing
- a small billing/invoicing workflow for project admin
- a knowledge graph generated by graphify for navigating the codebase

## What this codebase does

- Hosts the SimplifyOps.co website and blog
- Publishes Jekyll posts from `_posts/`
- Supports an approval-based content workflow through Hermes and Telegram
- Pulls context from the private brain repo when drafting content
- Includes billing/invoice automation scripts and templates
- Keeps a graphified map of the repo in `graphify-out/`
- Includes a local email workflow wrapper in `scripts/email-workflow.sh`

## Email workflow

Use the local wrapper for SimplifyOps-only email handling:

See also: `HERMES_PROJECT_ISOLATION_CHECKLIST.md`

- Review new mail in Inbox:
  - `scripts/email-workflow.sh review`
- Save a real Gmail draft via IMAP:
  - `scripts/email-workflow.sh draft <draft-file|->`
- After you explicitly say `approved`, schedule the send for exactly one hour later:
  - `scripts/email-workflow.sh send-after-approval approved <draft-file|->`

Notes:
- This is project-local, not a global Hermes setting.
- Drafts are saved into Gmail's Drafts folder via `himalaya message save`.
- Local copies of drafts and scheduled-send scripts live under `.email-workflow/` and are ignored by git.
- If `himalaya` is not on your WSL PATH, set `HIMALAYA_BIN` to the executable path first.

## Main parts

- `_posts/` — blog posts in Jekyll format
- `index.html` — site entry point / landing page
- `_layouts/` — Jekyll layouts
- `blog/` — blog listing page
- `billing/` — invoice generation workflow
- `logs/requests.md` — request log
- `plan-architecture/` — project and architecture docs
- `graphify-out/` — generated knowledge graph, report, and visualization

## How the content workflow works

1. Find a topic worth writing about
2. Check the brain repo for relevant prior material
3. Draft a post
4. Get human approval in Telegram
5. Commit the approved post to this repo
6. GitHub Pages auto-builds the site

## Start / stop notes

If you are working on the live system, start Hermes from the repo root so it picks up project-specific config.

To stop the local stack, stop the Hermes gateway and Honcho processes you started.

## Graphify notes

```bash

```

This refreshes:
- `graphify-out/GRAPH_REPORT.md`
- `graphify-out/graph.json`
- `graphify-out/graph.html`
